# PCE Extrapolation

Reproducible baseline for **Power Conversion Efficiency (PCE) prediction** on
the OPV²D donor-acceptor dataset (CycleChemist, 2026), with first-class support
for **extrapolation splits** so you can measure honest out-of-distribution
generalization while you iterate on new algorithms.

The default pipeline reproduces the paper's MOE² + P³ architecture
(R² ≈ 0.736 under random 5-fold; lower under scaffold/high-PCE holdout).
Y6 acceptor pairs are held out from the training pool by `01_prepare_data.py`
and reserved as the **stage-2 evaluation set**.

## End-to-end pipeline

### 1) Build the training pool (Y6 held out)

```bash
.venv/bin/python scripts/01_prepare_data.py
```

Produces `data/processed/opv2d_clean.csv` (Y6 acceptor pairs removed) and
`data/processed/opv2d_y6.csv` (the holdout). The report at
`data/processed/prepare_report.json` shows row counts.

### 2) Pretrain MOE² (3 stages)

```bash
PYTHONPATH=. .venv/bin/python scripts/02_pretrain_moe2.py \
    --config configs/baseline.yaml
```

You can disable any stage from the CLI:

```bash
# Skip stage 1 if MLM ckpt already exists
... pretrain.stage1_mlm.enabled=false

# Smaller / faster pretrain
... pretrain.stage1_mlm.epochs=20 pretrain.stage2_calc.epochs=30
```

### 3) Train PCE under an extrapolation split

```bash
PYTHONPATH=. .venv/bin/python scripts/03_train_pce.py \
    --config configs/baseline.yaml
```

Switch the split or any hyper-parameter from the CLI:

```bash
# Paper baseline: random 5-fold
... split.kind=random_kfold split.kwargs.n_splits=5

# Strict scaffold split on (donor_scaffold, acceptor_scaffold)
... split.kind=scaffold_pair

# Extrapolate to higher PCE (top 15% as test)
... split.kind=high_pce_holdout split.kwargs.test_quantile=0.85

# Leave-one-paper-out (all DOIs with ≥5 pairs)
... split.kind=leave_one_doi_out

# Quick smoke test
... trainer.epochs=4 trainer.warmup_epochs=2 split.kwargs.train_frac=0.6 split.kwargs.test_frac=0.2 split.kwargs.val_frac=0.2
```

Per-run outputs land at `outputs/<trainer.out_subdir>/`:
- `resolved_config.yaml` — exact resolved config (provenance)
- `fold{N}_best.pt`      — best checkpoint per fold (`{state_dict, y_mean, y_std}`)
- `fold{N}_predictions.csv`
- `fold_summary.csv`, `summary.json`

### 4) Stage-2 evaluation on Y6 (or any CSV)

```bash
PYTHONPATH=. .venv/bin/python scripts/04_evaluate_y6.py \
    --config configs/baseline.yaml \
    eval.fold_ckpt=outputs/pce_run/fold1_best.pt \
    eval.csv=data/processed/opv2d_y6.csv
```

## How to add a new algorithm

The framework is split-/encoder-/predictor-agnostic. Adding a variant means
**dropping one file + one yaml**; the training loop and CLI do not change.

### Add a new encoder

1. Create `src/models/encoders/my_gnn.py`:

   ```python
   from .. import register_encoder

   @register_encoder("my_gnn")
   class MyGNN(nn.Module):
       def __init__(self, in_channels, edge_dim, hidden_channels, out_channels,
                    regression_targets, heads, dropout_rate, **_):
           ...
       def encode_nodes(self, x, edge_index, edge_attr): ...    # required by P3
       def forward(self, x, edge_index, edge_attr, batch, task_type, batch_size=None):
           ...
   ```

2. Import it in `src/models/encoders/__init__.py`:
   `from . import my_gnn`

3. Use it: `--config configs/baseline.yaml encoder.kind=my_gnn predictor.kwargs.encoder_kind=my_gnn`

### Add a new predictor

1. Create `src/models/predictors/my_predictor.py`:

   ```python
   from .. import register_predictor, build_encoder

   @register_predictor("my_pred")
   class MyPredictor(nn.Module):
       def __init__(self, ...): ...
       def load_pretrained_encoders(self, state_dict): ...   # optional but recommended
       def freeze_encoders(self, freeze=True): ...           # optional, called by warmup
       def forward(self, donor, acceptor) -> torch.Tensor: ...
   ```

2. Import it in `src/models/predictors/__init__.py`.
3. Use it: `predictor.kind=my_pred`.

### Add a new split

1. In `src/data/splits.py`:

   ```python
   @register_split("my_split")
   def my_split(df, *, your_kw=...) -> list[Fold]:
       ...
       return [(train_idx, val_idx, test_idx)]
   ```

2. Use it: `split.kind=my_split split.kwargs.your_kw=...`

`Fold` = `(train_idx, val_idx, test_idx)` numpy int64 arrays (val may be empty).

## Built-in split strategies

| `split.kind`            | Test definition                                                            | Folds   |
|-------------------------|-----------------------------------------------------------------------------|---------|
| `random_kfold`          | uniform K-fold (paper baseline; **not** extrapolation)                      | K       |
| `scaffold_acceptor`     | unseen acceptor Bemis–Murcko scaffold                                       | 1       |
| `scaffold_pair`         | unseen `(donor_scaffold, acceptor_scaffold)` tuple                          | 1       |
| `acceptor_disjoint`     | acceptor canonical SMILES never appears in train                            | 1       |
| `high_pce_holdout`      | top-q quantile of PCE held out (extrapolate to higher efficiency)           | 1       |
| `leave_one_doi_out`     | one fold per DOI with ≥`min_doi_size` pairs                                 | many    |

## Configuration

We use **OmegaConf** (the library that powers Hydra), but skip Hydra itself.
Each script takes:

```bash
python scripts/<x>.py --config configs/<file>.yaml [dot.path=value]...
```

Overrides use OmegaConf's dot-list syntax, so anything in the yaml tree is
reachable from the CLI without writing extra parsing code:

```bash
python scripts/03_train_pce.py --config configs/baseline.yaml \
    split.kind=high_pce_holdout \
    split.kwargs.test_quantile=0.9 \
    encoder.kwargs.hidden_channels=256 \
    trainer.lr=2e-4 trainer.epochs=200
```

The resolved config is dumped next to every run for reproducibility.

## Reproducibility checklist

Set automatically by `set_seed(seed)`:
- Python `random`, NumPy, PyTorch (CPU + CUDA), `PYTHONHASHSEED`.
- `cudnn.deterministic = True` only if `set_seed(deterministic=True)` is called
  (default off — matches the paper, faster).

Each PCE run also writes:
- `outputs/<run>/resolved_config.yaml` — full config including overrides
- `outputs/<run>/fold_summary.csv` — per-fold metrics
- `outputs/<run>/fold{N}_predictions.csv` — per-row predictions

Pretrain runs write:
- `checkpoints/moe2_{mlm,calc,exp}.pt`
- `checkpoints/moe2_{mlm,calc,exp}_history.json`, `*_best.json`

## Two-stage evaluation rule

**Stage 1 (algorithm iteration):** train and tune on `opv2d_clean.csv` with
your chosen extrapolation split. *Never look at Y6 numbers during this phase.*

**Stage 2 (final assessment):** with the algorithm frozen, run
`scripts/04_evaluate_y6.py` on `opv2d_y6.csv` (or any external CSV) using a
representative fold checkpoint. Report Y6 numbers separately from the
within-OPV²D metrics.
